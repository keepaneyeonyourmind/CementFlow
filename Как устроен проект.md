# CementFlow — как устроен проект

## Что делает каждая часть

| Часть | Простыми словами | Зачем нужна |
| --- | --- | --- |
| Android | Система, на которой работает мобильное приложение | Показывает приложение на телефоне или в эмуляторе. |
| Kotlin | Язык программирования | На нём команда пишет код приложения и сервера. |
| Jetpack Compose | Набор инструментов для экранов Android на Kotlin | Позволяет описывать на Kotlin кнопки, поля и содержимое экранов. |
| Spring Boot | Набор инструментов для серверных приложений | Помогает принимать запросы приложения, проверять данные и работать с базой. |
| PostgreSQL | Система управления базой данных | Хранит общие товары, заказы и данные доставки. |
| Gradle | Инструмент сборки и управления зависимостями | Собирает проект и загружает нужные библиотеки в рамках настройки проекта. |

## Как части общаются

```text
Пользователь → приложение Android → сервер Spring Boot → PostgreSQL
                  ↑                     ↑                    |
                  └────── ответ ────────┴────────────────────┘
```

Например, пользователь оформляет заказ. Приложение отправляет введённые данные серверу; сервер проверяет их и сохраняет заказ в PostgreSQL. Затем сервер возвращает ответ, который приложение показывает пользователю. База не подключается напрямую к приложению: её настройки и пароль остаются на стороне сервера.

Для учебного показа сервер и база размещаются на компьютере. Чтобы приложение получало общие данные, оно должно иметь соединение с сервером. Адрес для эмулятора и адрес для физического телефона могут отличаться; конкретную настройку определим при подготовке демонстрации.

## В каком порядке создаются функции

Первые четыре блока ниже реализованы и проверены на эмуляторе до последнего изменения дизайна. Новый внешний вид ещё необходимо визуально проверить.

1. **Общая основа:** стартовый экран приложения, каркас сервера и понятные инструкции по запуску.
2. **Общие данные:** согласовать конкретные поля и правила заказов и доставки, затем описать запросы приложения к серверу и таблицы PostgreSQL.
3. **Три учебных модуля:** калькулятор, каталог и заказ, управление доставкой.
4. **Объединение:** связать приложение, сервер и базу; проверить сохранение заказа и смену статусов после отдельного согласия на проверки.

Калькулятор рассчитывает ориентировочную стоимость на учебных данных и не заменяет расчёт технолога. Для учебного примера используются три условные марки и цены; их можно уточнить с командой. Заказ содержит один товар, количество, учебные имя, телефон и адрес. Последовательность статусов доставки из плана: «ожидает → назначена → в пути → доставлена».

## Термины

- **API** — согласованный набор запросов и ответов между приложением и сервером.
- **Зависимость** — готовая библиотека, которую проект подключает для нужной функции.
- **Сборка** — превращение исходного кода и ресурсов в запускаемую программу.
- **Эмулятор** — программа на компьютере, имитирующая Android-устройство.
- **Репозиторий Git** — папка проекта с историей изменений. Создание коммитов выполняется только по поручению пользователя.

## Важно для первой версии

Все данные и цены демонстрационные. Система не подтверждает реальную цену, наличие товара или возможность доставки. Настоящей авторизации в первой версии нет; роли переключаются для демонстрации. Пароли не хранятся в файлах проекта и истории Git. PostgreSQL установлена с согласия пользователя; запуск проверок также согласован.
